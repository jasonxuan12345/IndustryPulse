# P5 验收记录：真实交易日历

日期：2026-10-19（Asia/Shanghai）。目标：补上唯一已知会影响 STRICT 正确性的
未决项——没有真实交易日历，B 级发布证据的"次一交易日 09:30"会静默算错。

## 1. 结论

用**可验证证据**推导出上期所 2026-01-05 ~ 2026-09-30 的交易日历：**181 个交易日**，
探测 195 个工作日。经两个独立来源交叉验证一致。

产物：`data/shfe-calendar-2026.json`（`data/` 不入 Git，可重跑生成）。

## 2. 三个"看起来像日历"的陷阱

| 来源 | 表象 | 实测 | 结论 |
|---|---|---|---|
| `/data/calendar/calendar_2026.dat` | 134 条 `tradeDate` | 只占 261 个工作日的 51.3%，缺 10-20/21/22 等正常交易日，带 `delivery`/`tradeLastDate` | **交割/事件日历**，不可用 |
| `/data/config/js/calendar-data.js` | 按年份的 `trade` 日期串 | 2026 年 265 条，含 **104 个周末**与国庆当天 | **含夜盘/活动标记**，不可用 |
| `/data/config/js/trade-data.js` | 日期串 | 连续自然日 | 非交易日历 |

三次都差一点误用。若任一个被当作 `trading_days`，PIT 选择会跳过真实交易日而
不报错——正是本项目最需要防的静默失效。

## 3. 采用的方法：以"是否存在官方日行情文件"为证据

```text
GET/HEAD https://www.shfe.com.cn/data/tradedata/future/dailydata/kx{YYYYMMDD}.dat
  200 -> 该日有官方日行情 -> 交易日（直接证据）
  404（重试一次仍 404） -> 该日无行情文件 -> 非交易日
  其它状态 / 网络异常 -> 抛错中止，绝不推断
```

护栏：

- **未来日期一律拒绝**：结束日必须早于 `today - 2 天`，避免把"文件还没发布"
  误判成"不交易"。（实测 2026-10-20 是交易日，但当日行情文件尚未发布 → 404。）
- 周末不探测，直接排除并记入证据。
- 全部探测结果写入证据行并取 sha256，作为日历的 `source_sha256` 出处指纹。
- 区间内零交易日直接拒绝（说明端点或逻辑错了）。

## 4. 交叉验证（两个独立来源）

**SSE 休市安排公告**（上交所公告文本，独立于 SHFE 行情）：

| 日期 | 公告结论 | 推导日历 | 一致 |
|---|---|---|---|
| 2026-09-25 | 中秋节休市（9/25–9/27） | 休市 | ✅ |
| 2026-09-28 | 节后照常开市 | 交易日 | ✅ |
| 2026-01-01 | 元旦休市 | 休市 | ✅ |
| 2026-01-05 | 元旦后首个交易日 | 交易日 | ✅ |

**交割日历日期集合**：区间内 106 个交割日 **全部**落在推导出的交易日集合内（0 例外）。
交割只发生在交易日，这是独立的一致性证据。

## 5. 接入

`compare-modes` 新增 `--calendar`，把交易日历注入 `DuckDBObservationRepository`，
使 B 级（只知日期）发布的"次一交易日 09:30"使用真实日历而不是 `+1 自然日` 回退：

```powershell
industrypulse calendar derive --from 2026-01-01 --to 2026-09-30 `
  --out data/shfe-calendar-2026.json --interval 0.15
industrypulse calendar validate data/shfe-calendar-2026.json
industrypulse compare-modes ... --calendar data/shfe-calendar-2026.json
```

`calendar validate` 现在优先采用文件内声明的 `exchange`，不再被 CLI 默认值覆盖。

## 6. 残余风险（明确记录）

- **只覆盖 2026-01-05 ~ 2026-09-30**：更早年份需逐段推导（同一条命令，改 `--from/--to`）。
  跨越区间之外的 as_of 查询，`TradingCalendar.covers()` 会返回 False，不会假装覆盖。
- **404 的语义**依赖"历史日期必有终态"。已用重试 + 未来日期护栏降低风险；
  若交易所某天临时撤下文件，该日会被误判为非交易日。这是本方法已知的局限。
- 目前只有日行情端点这一条证据链；理想情况应再叠加交易所年度休市公告的自动解析
  （SSE 公告正文可解析，但列表页分页是 JS 渲染，元旦那条拿不到，故本轮未自动化）。
- 推导过程每次约 195 次 HEAD 请求（间隔 0.15s），属于一次性运维动作，不应高频重跑。

## 4. 多年度回填：受阻（重要运维发现）

尝试 `--from 2021-01 --to 2026-09`（约 200 份文档）时：

1. 列表分页到 `index_67.html` 返回 **404** → 已修复为"列表到底"的正常终止；
2. 随后 **国家统计局站点开始对所有页面返回 JavaScript 挑战页**
   （`Please enable JavaScript`），包括首页。此前 P4/P5/P6 的密集请求触发了站点保护。

**结论**：站点有反爬/限流保护，200 份文档的密集回填不可行。后续做法：

- 必须大幅降速（≥5s/请求）并分散到多天；
- 增加"被挑战即停并告警"的检测（当前会把挑战页当成 0 条公告，属静默失败风险）；
- 或改用官方批量数据接口（需另行核验许可）。

本次未能把历史拉长到 5 年，现有数据仍为 2025-07 ~ 2026-09（183 个观测）。

**已发现的静默失败风险**：JS 挑战页返回 200 且无公告链接，`discover` 会认为"本页无新增"而正常结束，不报错。这是一个待修缺陷（应在解析前检测挑战页特征）。

## 5. 本轮修复的缺陷

**信号取最早期而非最新期**（真实多期数据才暴露）：
`build_rule_signals` 原用 `selection.selected[0]`，而 `select` 返回**全部可见所属期**，
导致规则永远停留在最早一期（回测只成交 1 笔）。改为按 `observation_start` 取最新，
并在最新期数值缺失时空仓 + 告警。已加回归测试。
